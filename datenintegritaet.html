Datenintegrität

Wie sorgt eine Datenbank dafür, dass ihre Daten sinnvoll, korrekt und miteinander vereinbar bleiben? Entdecke drei Arten von Integritätsbedingungen anhand einer kleinen Schul-Datenbank.

GrundideeDrei Arten1. Wertebereich2. Datensatz3. ReferenzenWissen testen

1. Die Grundidee

Eine Datenbank speichert Informationen. Datenintegrität bedeutet, dass diese Informationen bestimmten Regeln entsprechen und zusammen keinen Widerspruch bilden. Ein Datenbankmanagementsystem (DBMS) kann solche Regeln bei Einfügen, Ändern und Löschen prüfen.

Stell dir eine Schul-Datenbank vor: Sie verwaltet Schülerinnen und Schüler, Kurse und die Zuordnung zu Kursen. Was passiert, wenn jemand eine unmögliche Note einträgt oder ein Kurs gelöscht wird, obwohl noch Lernende darin eingetragen sind?
Daten ändern→Regeln prüfen→gültig: speichern/ungültig: ablehnen oder geregelt behandeln

2. Drei Arten von Integritätsbedingungen

Datenfeldebene

Wertebereichsintegrität

Ist dieser einzelne Wert erlaubt?

Beispiel: Eine Note darf nur 1 bis 6 sein.

Datensatzebene

Datensatzintegrität

Ist der gesamte Datensatz in sich korrekt?

Beispiel: Eine Schüler-ID muss eindeutig sein und Pflichtfelder dürfen nicht fehlen.

Beziehungsebene

Referentielle Integrität

Passen die Verknüpfungen zwischen Tabellen?

Beispiel: Eine Kurszuordnung darf nur auf einen existierenden Kurs zeigen.

Merksatz: Einzelwert – ganzer Datensatz – Verbindung zwischen Tabellen.

3. Wertebereichsintegrität: Ist der Wert erlaubt?

Eine Spalte hat einen erlaubten Wertebereich. Der kann zum Beispiel durch einen Datentyp, einen Zahlenbereich oder eine Liste erlaubter Werte festgelegt sein.

Beispiel: Tabelle Leistung
Schüler-IDFachNotePrüfung
101Informatik2gültig
102Informatik5gültig
103Informatik8ungültig
104Informatik„gut“ungültig, wenn eine Zahl erwartet wird
Warum sind die letzten beiden Einträge problematisch? Die Note 8 liegt außerhalb des festgelegten Bereichs 1–6. Der Text „gut“ ist kein Zahlenwert, wenn die Spalte eine Zahl erwartet.

Probiere es selbst

In dieser Mini-Prüfung gilt: Die Note muss eine ganze Zahl von 1 bis 6 sein.

In SQL könnte eine solche Regel beispielsweise mit CHECK (Note BETWEEN 1 AND 6) umgesetzt werden.

4. Datensatzintegrität: Ist der ganze Eintrag korrekt?

Ein Datensatz besteht aus mehreren Feldwerten. Auch wenn jeder Wert für sich erlaubt ist, kann der gesamte Eintrag gegen Regeln verstoßen.

Beispiel: Tabelle Schueler
Schüler-IDNameKlasseBewertung
101Mina Yilmaz11agültig
102Jonas Weber11bgültig
101Lea Sommer11aungültig: ID doppelt
103(leer)11aungültig, falls Name Pflicht ist

Hier gelten zwei Regeln: Die Schüler-ID ist eindeutig (Primärschlüssel), und der Name darf nicht leer sein (NOT NULL). Die ersten beiden Zeilen erfüllen beide Regeln; die folgenden verletzen jeweils eine davon.

Wichtig: In der Praxis wird „Datensatzintegrität“ manchmal als Sammelbegriff verwendet. In diesem Lernmodul meint es Regeln, die einen vollständigen Datensatz betreffen, zum Beispiel eindeutige Schlüssel und Pflichtfelder.

Mini-Aufgabe

Die Tabelle verlangt eine eindeutige ID und einen ausgefüllten Namen. Was ist mit dem Eintrag (ID 105, Name „Sam“, Klasse leer), wenn auch die Klasse ein Pflichtfeld ist?

5. Referentielle Integrität: Stimmen die Verknüpfungen?

Relationale Datenbanken verteilen Informationen auf mehrere Tabellen. Eine Fremdschlüssel-Spalte verweist auf einen Datensatz in einer anderen Tabelle. Normalerweise darf sie nur auf einen Datensatz zeigen, der tatsächlich existiert.

Tabelle Kurs
Kurs-IDKursname
K10Informatik
K20Biologie
K30Geschichte
Tabelle Belegung
Schüler-IDKurs-ID (Fremdschlüssel)Prüfung
101K10gültig
102K20gültig
103K99ungültig: Kurs fehlt

Die Belegung mit K99 ist fehlerhaft, weil es diesen Kurs in der Tabelle Kurs nicht gibt. Der Fremdschlüssel verhindert, dass eine Belegung auf einen nicht vorhandenen Kurs verweist.

Was soll beim Löschen eines Kurses passieren?

Angenommen, Kurs K10 wird gelöscht, aber Schüler 101 ist noch dafür eingetragen. Dafür gibt es unterschiedliche Regeln:

RegelWas passiert?Wann sinnvoll?
RESTRICT / NO ACTIONDas Löschen wird verhindert, solange noch Belegungen auf den Kurs verweisen.Wenn zuerst die Belegungen bewusst entfernt oder geändert werden sollen.
CASCADEDie zugehörigen Belegungen werden automatisch mit gelöscht.Wenn abhängige Einträge ohne den Hauptdatensatz keinen Sinn mehr haben.
SET NULLDie Fremdschlüssel in den Belegungen werden auf NULL gesetzt.Wenn eine Belegung ohne zugeordneten Kurs bestehen bleiben darf und die Spalte NULL zulässt.
Merke: CASCADE ist praktisch, kann aber viele Einträge auf einmal löschen. Deshalb muss die Regel zur Bedeutung der Daten passen.
